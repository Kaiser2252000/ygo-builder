## What Went Well

- **Consistent architecture pattern**: Every story followed the established context-value/provider/hook pattern. DeckContext was extended cleanly across stories (CRUD → mutation methods → sort/clear → save) without architectural drift.

- **Code reviews caught real bugs consistently**: Every story had reviews with actionable patch findings. Race conditions, stale closures, null-safety gaps, and fragile selectors were caught before merge. Stories 2.3-2.6 had particularly thorough reviews (12, 10, 6, and 8 patch findings respectively).

- **Frontend test infrastructure matured**: What started as "under-tested" in Epic 1 became a reliable safety net by Epic 2's end. Story 2.6's 66-test suite gives confidence that Save/Import/Export/Upload flows work correctly.

- **Pure function sort strategy**: Story 2.5's `sortCardIds` was implemented as a pure utility function with isolated unit tests — clean, testable, and fast (under 500ms for 60 cards).

- **YDK import/export correctly handled edge cases**: Unknown card IDs collected separately, malformed content caught with descriptive errors, empty zones omitted from export, zone reset on import — all per spec.

- **Deferred work tracked systematically**: Each story's reviews consistently separated patch findings (apply now) from deferred findings (pre-existing / out of scope), with deferred items written to `deferred-work.md`.

- **Previous retro lessons applied well**: All 5 action items from Epic 1 retro were addressed — frontend test harness created, FR3 tracked in Story 2.4, response envelope and service delegation patterns reused consistently.

## Challenges

- **Backend tests never expanded**: Story 2.1 created the backend test suite, but stories 2.3-2.6 touched backend code (batch endpoint, cover/export/import) without adding corresponding backend tests. The `backend/tests/` directory is empty. Test coverage gap.

- **Stale closures and race conditions recurred across stories**: Stories 2.3 (useEffect cleanup), 2.5 (setTimeout in handleSortZone), and 2.6 (saveDeck state.decks closure) all had review findings around stale state in async operations. This pattern is easy to introduce and easy to miss without review.

- **Error handling inconsistencies between frontend and backend**: The `apiPost`/`apiPut` helpers swallow backend error codes (return `HTTP_ERROR` for all non-OK responses). The frontend's PARSE_ERROR checks in import logic work in tests (which mock directly) but would never trigger with the real `apiPost` because error codes are lost. Story 2.6's review flagged this but it was deferred as pre-existing.

- **Frontend component test location drift**: Epic 1 tests went in `tests/frontend/components/`, but Epic 2 tests landed in `frontend/src/__tests__/`. Different agents made different choices. Both patterns work but should be unified.

- **Button component constraint surfaced repeatedly**: The Button only supports `"default" | "ghost" | "destructive"` — no `"outline"`. This was documented but caused friction in stories 2.4-2.6 where Export/Import buttons needed a less prominent variant.

- **No `tsc` npm script**: TypeScript checking requires `npx tsc --noEmit` directly — no npm script was set up. Noticed during story 2.6 but never fixed.

## Review Feedback Patterns

Reviews across all 6 stories showed consistent themes:

**Most common patch categories:**
1. **Stale closures / race hazards** (stories 2.3, 2.5, 2.6): `useEffect` cleanup, setTimeout closures, captured `state` in `useCallback`
2. **Null/undefined safety** (stories 2.3, 2.4, 2.5): Missing guards on optional data, `== null` vs `=== null` patterns
3. **Defensive state updates** (stories 2.4, 2.5): Splicing without bounds checks, missing defensive copies of sorted arrays
4. **Error handling gaps** (stories 2.3, 2.4, 2.6): API failures silently emptying state, no visual feedback on silent failures

**Recurring deferred items:**
- Keyboard accessibility for deck slots (deferred in 2.3, noted again in 2.4)
- No runtime API response validation (deferred in 2.2)
- Oversized decklist truncation (deferred in 2.4)
- No per-card copy limit enforcement on frontend (deferred in 2.4)

## Key Lessons

1. **Add backend tests when touching backend code.** All three stories that touched backend (2.3: batch endpoint, 2.6: cover/export/import) should have added backend tests. Write route/service tests alongside the implementation.

2. **Stale closure prevention pattern**: When `useCallback` captures state, use a ref for the latest value (as applied in Patch 3 of Story 2.6). When using `setTimeout`, include cleanup and verify closures capture correct render.

3. **API error propagation matters**: If `apiPost`/`apiPut` swallow backend error codes, frontend error branching (like PARSE_ERROR vs IMPORT_ERROR) doesn't work in production. Either fix the API helpers to propagate backend errors, or branch on HTTP status codes instead.

4. **Unify test file location**: Pick one pattern (`src/__tests__/` or `tests/frontend/components/`) and stick with it. The drift happened because Epic 1 and Epic 2 used different agents.

5. **Every new component region deserves a visual review**: Zone backgrounds, frameType colors, and slot hover states are visual details that are hard to validate from code alone. Build and visually inspect after each zone/slot story.

6. **Deferred work should have explicit follow-up gates**: Several deferred items (keyboard accessibility, API error propagation) affect the next epic. Document them with specific owner and trigger conditions, not just a list.

## Deferred Work

Items deferred during Epic 2 that affect Epic 3 or later:

- `_deck_cache` race condition — module-level singleton without write lock
- `request_validation_exception_handler` never registered in FastAPI
- Path traversal via deck_id — no sanitization on any endpoint
- No URL length protection for `fetchCardsByIds` — comma-joined IDs could exceed limits
- `fetchCardsByIds` called on every decklist reorder — unnecessary server calls
- `update_deck` validates every card individually — up to 90 lookups per save
- `addCardToZone` negative slotIndex inserts at wrong position
- `removeCardFromZone` no bounds check on slotIndex
- API helpers (`apiPost`, `apiPut`, `apiPostForm`) swallow backend error codes
- Keyboard accessibility for deck slots (deferred from 2.3, 2.4)
- DeckLibrary tests not upgraded to ToastProvider (pre-existing)

All deferred items are documented in `_bmad-output/implementation-artifacts/deferred-work.md`.
